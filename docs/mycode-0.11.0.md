## 与 Cindy 的本地能力适配

参考 `makecindy/cindy` 的开源快照 `bfb95c3`：供应商左侧列表/右侧模型管理、UsageHistorySection、StorageManagementCard。没有使用其账号、云同步或私有服务。

- 供应商的原生连接 ID 跟随每轮模型归属；同名模型来自不同连接时不混算。
- 日期统计使用每轮 startedAt，而非会话最后更新时间；无时间戳的旧消息仅计入所有时间。
- 用量仅取真实返回的输入/输出/缓存数值，不估算金额或缺失 Token。
- 存储管理按 MyCode 的 SQLite、缓存路径和草稿机制实现，不照搬 Cindy 的媒体 CAS 结构及云端/跨设备统计。
- 日志清理仅处理应用目录中超过 7 天的 .log；不沿符号链接或 Windows 目录联接遍历。
- 附件扫描检查保存的会话、笔记与活动草稿，清理前再次检查引用；文件转移到应用数据目录 backups/media-*，manifest.json 记录原路径。恢复备份仍占用磁盘，不把转移宣称为释放总磁盘容量。
- 数据库压缩先用 SQLite VACUUM INTO 创建一致性备份，随后执行 VACUUM 和 optimize；不删除会话正文。

## 使用变化

- OMP、FX、Antigravity、ZCode 不再提供新任务、运行、安装或导入入口。旧会话保留原智能体标识与内容，可更换受支持的智能体继续。
- 新安装或未设置过位置时工作区默认在右；已明确设置左侧的用户不被覆盖。
- 活动组运行时自动展开；手动折叠优先，完成后默认收起。仅显示智能体实际发送的工具、命令与思考事件，不编造内部推理。
- Windows 无头窗口修复通过 Node 启动预加载继承给 agent-browser 等子进程，只隐藏 headless 浏览器；已经启动的旧后台进程需结束后以新版本重新启动。
- GitCode 先验证仓库访问，再保存新令牌，失败不会覆盖已有令牌；配置成功后才出现收件箱入口。

## 验证边界

发布记录附构建和测试结果。浏览器界面验收使用模拟原生返回值；不代表真实 API Key、GitCode 账号、SSH 主机或所有第三方 CLI 的在线验收。仓库中不包含用户凭据。

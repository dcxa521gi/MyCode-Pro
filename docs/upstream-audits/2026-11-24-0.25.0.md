## 已有基础，本次未冒充新增

- Claude/Codex 多账号登录、账号配置目录和凭据隔离原已存在；新增的是模型组对这些账号的调度入口和真实发送接入。
- 编排已支持独立工作副本、文件范围、串并行依赖、主管审查、持久化与停止恢复；新增的是整阶段原子委派、阶段身份及准备期的轮次检查。
- 远程命令发件箱、回执幂等、会话增量同步、断线退避已经存在；新增的是统一模型目录读取状态。
- IM 插件独立更新属于 0.24.1；本地工作流插件是新增的一类能力，不重复计算原有 IM 更新。

## 仍未融合的具体部分

| 部分 | 状态和原因 | 后续实现边界 |
| --- | --- | --- |
| Cindy 动态 ACP 插件引擎及账号登录协议 | 未融合；MyCode 目前是固定 Harness 注册表，没有 Cindy 的插件 worker、引擎声明/批准注册表、账号目录协议 | 先实现独立动态 Harness 生命周期和固定账号目录协议，再接登录/用量/会话；不能用工作流 JSON 冒充 ACP 插件 |
| Cindy 跨电脑模型组、供应商分享、手机组选择 | 未融合；依赖不同的 Device Link 身份/分享协议 | 在 MyCode Host 协议中增加显式组路由与账号授权描述，完成双方身份与撤销验证；不接入 Cindy 云 |
| Cindy 已进行任务的自动账号切换、重新启动引擎、额度恢复继续 | 未新增；本版仅新会话首次选路，保留已有人工切账号能力 | 需要按实际 CLI 校验会话移交、文件修改后不重复执行和错误分类，不能盲目重放 |
| Cindy 插件 JS worker、网页面板、远程插件、官方插件供应商向导 | 未融合；本版本地插件协议仅声明式命名工作流与原生表单 | 下一阶段独立设计权限、进程终止和资源边界；保留当前表单协议 |
| Synara 完整 Agent Gateway、原生 ACP 子代理、Hub 通知与数据库迁移 146 | 未融合；MyCode 使用自己的持久化编排状态与受控 CLI | 仅复用阶段/回执/原轮次边界的设计，保留 MyCode 已验证的工作副本及审批逻辑，不运行不兼容数据库迁移 |
| Synara Antigravity 专项更新 | 不启用；用户明确移除的代理 | 只吸收通用编排约束，不重新注册此代理 |
| Cindy 其余核对条目 | 未因本版而宣称全量融合 | 继续以 0.24.1 的逐提交清单及本次追加清单追踪，逐项适配后新增事件 |
